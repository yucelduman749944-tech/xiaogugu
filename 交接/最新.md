## 重要決定與原因
- **不用建置工具**：純 HTML/CSS/JS，`site/` 就是網站根目錄。網站只有一頁，加框架只會增加維護成本。
- **repo 設成公開**：你選的。GitHub Pages 用公開 repo 免費，但密碼、API key 絕對不能放進 repo，要放在 `.env`（已經設定成不上傳）。
- **頁面內的圖片、CSS、JS 保持相對路徑**：這樣本地預覽和線上都能用，換網域也不會壞。只有 `og:url`、`og:image`、`canonical` 寫完整網址。
- **Pages workflow 拆成 build 和 deploy 兩個 job**：原本寫成一個 job 時，連續兩次發生「找不到上傳檔案」而部署失敗，改成 GitHub 官方範本的寫法後就正常了。
- **分享圖用 HTML 排版，再用 Chrome 截圖產生**：之後改文案只要改 HTML 重跑指令，不用另外開設計軟體。分享圖不受「單張 < 250KB」的規則限制，因為訪客不會載入它。
